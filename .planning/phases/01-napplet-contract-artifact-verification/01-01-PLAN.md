## Trust Boundaries

| Boundary | Description |
|---|---|
| candidate metadata → manifest parser | Registry/source/release metadata is untrusted until schema, integrity, and mapping checks pass. |
| manifest → local executable | Only reviewed absolute binaries and literal argv may cross into subprocess execution. |
| subprocess output → evidence | Tool output is untrusted and must be bounded, digested, and unable to alter verdict structure. |

## STRIDE Threat Register — ASVS L1

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-01 | Tampering | `PromotionManifest` candidate identity | high | mitigate | Require all D-04 pins, canonical ID, exact integrity/source/executable mapping, and block incomplete candidates in `schema.ts`/`candidate.ts`. |
| T-01-02 | Information Disclosure / Tampering | `runHermeticCommand` | high | mitigate | Absolute allowlist, argv-only spawn, scrubbed environment, bounded output/resources, isolated cwd, and failure evidence. |
| T-01-04 | Tampering / Repudiation | evidence bundle | high | mitigate | Canonical digest for every layer and validation that refuses missing or altered report links. |
| T-01-SC | Tampering | npm/package candidate intake | high | mitigate | No install in this plan; Plan 02 provides a blocking-human legitimacy checkpoint for every `[SUS]` package before image intake. |
| T-01-06 | Denial of Service | test subprocess | medium | mitigate | Enforce wall-clock, output, process, CPU, and memory budgets and reap all children. |
</threat_model>
