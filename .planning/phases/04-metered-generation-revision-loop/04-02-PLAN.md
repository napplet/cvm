<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Coordinator -> PostgreSQL transaction | Validated but replayable inputs cross into irreversible money/session state. |
| Receipt/card records -> ledger postings | Protected usage facts become exact financial entries. |
| Stored ledger/session facts -> owner projection | Complete history must remain immutable, ordered, bounded, and owner scoped. |

## STRIDE Threat Register — ASVS L1

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-04-ATOMIC | Tampering | `finalizeMeteredAction` | high | mitigate | Deterministic lock order, `SERIALIZABLE`, unique identities, conservation checks, and failpoint rollback tests in Tasks 1–2. |
| T-04-REPLAY | Repudiation | receipts/postings/results | high | mitigate | Independent unique operation, provider-request, receipt, ledger, line-item, result, outbox, and artifact references plus durable exact replay. |
| T-04-EVIDENCE | Information disclosure | billing history | high | mitigate | Owner-scoped projection, explicit normalized allowlist, protected native evidence reference, bounded opaque cursor, and canary tests. |
| T-04-RETRY | Denial of service | SQL serialization handling | medium | mitigate | Existing bounded attempt/deadline policy, deterministic lock order, and tests that exhaust retries without provider redispatch. |
| T-04-QUARANTINE | Tampering | over-ceiling/unpriceable receipt | high | mitigate | No debit path, durable invariant/reconciliation record, and profile/card quarantine in both adapters. |
| T-04-SC | Tampering | database dependencies | high | mitigate | No package install or version change; existing pinned Kysely/pg confinement and Phase 3 adapter tests remain green. |
