<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Revision text -> serialized action | Untrusted text and stale identifiers request another paid mutation. |
| Model/worker/package/build output -> napplet harness | Indirect instructions may attempt authority expansion or false success. |
| Validation failure -> repair authorization | An agent-generated failure could become an autonomous spending loop. |
| Candidate evidence -> verified artifact version | Unsafe or incomplete work must never replace the prior artifact. |

## STRIDE Threat Register — ASVS L1

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-04-RACE | Tampering | `reviseSession` | high | mitigate | Owner/expected-version/lineage/idempotency fences and barrier concurrency tests in Task 1. |
| T-04-INJECTION | Elevation of privilege | `ProjectNappletHarness` | high | mitigate | Strict request/result schemas, fixed workflow/commands, existing scoped grants, approved surfaces, server-owned policy/artifact gates, and hostile-content tests in Task 2. |
| T-04-HONESTY | Spoofing | artifact outcome | high | mitigate | All-gates-pass union branch is the sole artifact advance input; failure cases retain prior artifact and safe evidence. |
| T-04-REPAIR | Denial of service | automatic repair | high | mitigate | Versioned maximum one, separate authorization, origin evidence binding, concurrency fence, and second-trigger denial in Task 3. |
| T-04-DIAGNOSTIC | Information disclosure | failed/incomplete status | high | mitigate | Closed safe diagnostic schema and canary tests exclude raw prompt/source/reasoning/credentials/grants/provider evidence. |
| T-04-SC | Tampering | napplet skill/CLI/toolchain text | high | mitigate | Consume promoted immutable compatibility identity through existing gates; package text is data and cannot change policy/pins/commands. |
