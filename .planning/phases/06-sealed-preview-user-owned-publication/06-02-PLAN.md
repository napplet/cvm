<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| verified manifest -> capability review | Manifest fields remain untrusted until strict parsing, normalization, and duplicate/conflict checks. |
| preview service -> host | The host receives an exact descriptor and a least-authority grant. |
| iframe/runtime -> status projector | Runtime messages are attacker-controlled and cannot add trusted fields or actions. |

## STRIDE Threat Register (ASVS L1, block high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-06-02-T | Tampering | descriptor/artifact | high | mitigate | Recompare exact artifact, manifest, aggregate, evidence, entrypoint, and capability hashes before issuance. |
| T-06-02-E | Elevation of privilege | iframe grant | high | mitigate | Enforce allow-scripts only, zero same-origin, short expiry, and an exact read-only artifact permission. |
| T-06-02-I | Information disclosure | runtime status | medium | mitigate | Use explicit owner-safe projection; discard raw runtime messages and provider details. |
| T-06-02-D | Denial of service | capabilities | medium | mitigate | Bound arrays/strings, reject duplicates, and use deterministic linear canonicalization. |
| T-06-02-S | Spoofing | runtime compatibility | high | mitigate | Derive compatibility only from verified manifest plus configured host variant and bind it into the digest. |
| T-06-SC | Tampering | hashing/runtime dependencies | high | mitigate | Use platform SHA-256 and existing locked dependencies only; add no install. |
</threat_model>
