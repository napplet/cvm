<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| service -> transactional store | Commands and observations are untrusted until schema/fingerprint/state validation. |
| concurrent replicas -> SQL authority | Multiple replicas may race the same intent/effect operation. |
| external observation -> persisted record | Provider/CLI observations can be partial, stale, duplicated, or forged. |

## STRIDE Threat Register (ASVS L1, block high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-06-04-T | Tampering | stored intent/effect | high | mitigate | Strict schema, fingerprint comparison, foreign keys, unique operation ids, and immutable terminal observations. |
| T-06-04-R | Repudiation | publication history | high | mitigate | Store command, intent, claim, observation, and linked record identities transactionally. |
| T-06-04-I | Information disclosure | JSON columns/errors | high | mitigate | Owner-safe/protected evidence references only; no secrets or raw provider payloads. |
| T-06-04-D | Denial of service | contention/retry | medium | mitigate | Immediate/serializable transactions, bounded retries, deadlines, and busy/pending status. |
| T-06-04-E | Elevation of privilege | effect claim | high | mitigate | Principal-scoped command and compare-and-set one-claim uniqueness per intent/effect. |
| T-06-04-S | Spoofing | external observation | high | mitigate | Require original stored operation id and expected effect kind before recording. |
| T-06-SC | Tampering | database/runtime dependencies | high | mitigate | Reuse locked Bun/SQLite/PostgreSQL stack and add no package install. |
</threat_model>
