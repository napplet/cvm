## Trust Boundaries

| Boundary | Description |
|---|---|
| candidate/topology/provider facts -> generated profile/config | Untrusted or incomplete facts must not select policy, code, secret values, or release claims. |
| repository source -> executable adapter/trust bundles | Entry-module hashing alone is insufficient when transitive code can drift. |
| protected observations/records -> trust-root material | Content hashes require independent candidate/input/freshness/status validation before becoming authority. |
