<interfaces>
- `ModelGateway.dispatch(intent, signal)` and `lookup` currently expose normalized usage but no idea/source input or proposal result. Extend the provider-neutral observation so one operation owns bounded prompt/prior-artifact input, usage/correlation, and a content-addressed `sourceProposalReference`; lookup-only recovery must return the same completed proposal without another provider call.
- `MeteredGenerationService` currently dispatches without idea context and later sends the original idea to `NappletHarness`. Replace that disconnect: a completed metered proposal reference is the worker input, and the worker must not call a model.
- Provider schemas and `PriceCardSchema` currently accept only `deterministic_fixture`; selection currently embeds `PHASE_04_DETERMINISTIC_PRICE_CARD` and a deterministic toolchain ID. Generalize these as explicit configured profile/card/toolchain inputs while retaining immutable normalization and maximum-charge checks.
- Existing `PreviewService` and `PreviewDescriptor` remain the ownership/expiry authority. HTTP may return the expiring immutable bytes selected by that descriptor; generation commands remain ContextVM-only.
- Official compatible host provenance: pin `@kehto/paja@0.19.0` from the official napplet source/package relationship. The published conformance CLI alone is not the full host. Runtime launch must consume a reviewed version/hash-pinned artifact rather than an arbitrary sibling checkout.
- Existing toolchain gaps are acceptance work: Chromium plus system dependencies are absent and the CLI binary is x86_64. The dev image must explicitly install the locked browser and support Apple Silicon through a verified native build or linux/amd64 container execution.
- The development worker preserves sealed-runner, manifest-command, hash, network, credential, and conformance guards but uses a separately identified local development image/adapter. Deferred production image promotion, registry digest, and operator approval from Plans 20/26 are not prerequisites and must not be reported as development failures.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser/ContextVM -> model adapter | Untrusted bounded prompt and prior-artifact reference enter a paid external effect. |
| Model output -> proposal store -> worker | Untrusted generated source crosses into isolated code execution. |
| Worker -> verified artifact/preview | Untrusted filesystem and command output request promotion into user-visible bytes. |
| Workspace -> compatible host -> napplet iframe | Host messages and capability requests cross origins and sandbox boundaries. |

## STRIDE Threat Register (ASVS L1; block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-07DEV53-01 | Tampering | Proposal reference and worker input | high | mitigate | Content/owner/session/action binding, size limits, immutable storage, and mismatch tests before worker launch. |
| T-07DEV53-02 | Repudiation | Provider usage and exact charge | high | mitigate | Provider correlation, normalized native usage, immutable price-card ID, one-operation lookup recovery, and SQL/evidence comparison. |
| T-07DEV53-03 | Elevation of privilege | Generated code execution | high | mitigate | Isolated contained worker, sealed surfaces/toolchain, blocked credentials/network, hard resource/time limits, and real conformance gate. |
| T-07DEV53-04 | Information disclosure | Preview/iframe | high | mitigate | Ownership/expiry authorization, separate origin, `allow-scripts` only, no credentials, and negative byte/message tests. |
| T-07DEV53-05 | Spoofing | Compatible host provenance | high | mitigate | Exact official revision/package/hash intake and readiness failure on integrity mismatch. |
| T-07DEV53-06 | Denial of service | Model/build/Chromium | medium | mitigate | User maximum, provider deadline, contained CPU/memory/time limits, bounded output, and cleanup. |
| T-07DEV53-SC | Tampering | package/toolchain intake | high | mitigate | Preserve root hashes; accept only version/hash-pinned development packages and reviewed host provenance, then run conformance before preview. |
</threat_model>
