# Publish verified napplets from applet.broker

Use the GSD quick workflow inline. Preserve active development data, ChatGPT credentials, generation fences and production deferrals.

## User decisions

- Visible working Publish action in the product workspace.
- Nostr identity options: Anonymous, NIP-07 (disabled when absent), and NIP-46 using a client-initiated nostrconnect QR code by default.
- Sign-in available from every step, including while generation is running. Publication requires an authenticated/selected signing identity; Publish is disabled before sign-in.
- Signing identity changes never alter or interrupt the active generation principal or request.
- Public workspace is a deployable static ContextVM client. All service commands, discovery, funding and publication go over signed encrypted ContextVM; only immutable assets/preview bytes use HTTP.
- Provider accounts and API keys belong to the CVM operator, never public bootstrap or product settings. Separate authenticated CVM admin manages provider credentials, immutable rate versions, and pending/active/finished job lists with details.
- Verified development builds are automatically published under the CVM identity to its own Blossom server and configured relay, with a copyable naddr for testing in other shells.
- CVM Blossom implements BUD-01/02/04/11 basics, accepting writes/mirrors only signed by its own CVM identity. Reads are public for shell testing.
- User publication is distinct: CVM constructs template; client obtains user's signature, discovers kind-10063 Blossom server list (manual fallback), mirrors verified blobs from CVM to user's servers, then submits the signed event. Show signing, per-server/file propagation and relay progress/failures. Never claim complete with missing blobs.
- Preserve existing subscription configuration while moving its controls to admin. Admin commands also use ContextVM; OAuth's provider callback remains a private operator authorization boundary.
- Persist a local project registry with owner pubkeys derived from verified CVM request identity. Listing accepts no owner/npub argument; detail, rename, preview and continuation enforce the same ownership. Return pending, active, verified, published, failed and unresolved stages. Selected NIP-07/NIP-46 identities sign encrypted CVM requests directly, so returning users can reopen their own projects from another browser. Anonymous work stays with its original key; signing in during work does not transfer ownership or interrupt it.

- Publish is contextual to the selected applet, as step 4 in the workspace, not a header button or modal.
- User publication uses NIP-65 write relays discovered through purplepag.es, with explicit manual fallback. Both relay and Blossom addresses use validated removable chips; optional NIP-66 relay suggestions require recent independent-monitor agreement. Never substitute the CVM relay for a missing user list.

- Your applets is a dedicated, bookmarkable static page with shared navigation, browser back/forward, and uninterrupted live generation. List both the selected account and this tab’s earlier anonymous projects using separate verified CVM requests from their actual keys; label ownership without transferring it. Recover legacy account-hash-only sessions on that proof and refresh in-progress status while the page is visible.
