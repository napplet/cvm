# Recover generated compiler failures through one bounded paid repair

Compiler validation failures are definitive local failures after a billable model operation. Preserve the failed action and receipt, feed its exact stored source plus bounded diagnostic into one new metered model operation, and return the repaired result when authorized. This is not a retry of an uncertain provider operation.

## Locked behavior

- Only a durable TypeScript validation failure is repairable. Provider ambiguity, worker interruption/timeout, infrastructure failure, artifact-policy denial, and settlement uncertainty never auto-dispatch another model call.
- The original action, failed proposal, validation report, and exact receipt remain immutable. A repair is a separate action, operation, budget reservation, receipt, and artifact version.
- Automatic repair is limited to one per root action and runs only when the user previously approved a workflow maximum covering the original charge plus a full second profile ceiling. Existing one-ceiling failures require an explicit new signed repair approval; never reinterpret or enlarge their historical maximum.
- Source and diagnostic reads are owner/session/action bound. Compiler output is bounded untrusted data; the service developer contract remains authoritative.
- Both configured-provider service mode and ChatGPT OAuth development mode use the same coordinator path. No provider-specific recovery logic, deployment machinery, or new queue is introduced.

## Acceptance

- A saved source proposal that fails TypeScript verification can be repaired once using that exact source and diagnostic; the returned success is a genuinely verified new artifact.
- The original failed action and charge remain queryable, and the repair has its own exact usage receipt.
- Automatic repair cannot exceed the signed workflow maximum; an old one-ceiling request performs no new call until the owner explicitly approves it.
- Concurrent calls and process restart converge on one repair action. Ambiguous provider/worker outcomes never dispatch a repair.
- A second compiler failure stops with retained evidence and a manual next action; it is not relabeled successful.
