# Recovery of ordinary funded generation

[Schema proposal and technical compatibility decision](https://github.com/napplet/cvm/issues/67) define the additive internal archive. This does not change public tools or authorize live effects.

The production graph retains a versioned encrypted copy of the complete owner-authorized command in the same PostgreSQL transaction that prepares its metered action and budget. The archive binds the original account, session, action, provider operation, idempotency key, full command fingerprint, admission, version, reservation maximum, profile, price card and toolchain. The caller's approved maximum can exceed the reservation; its exact original value stays inside the encrypted command. Recovery never reconstructs that value from current policy.

Encryption uses a random AES-GCM data key per command, wrapped under the mounted checkpoint KEK. Both layers authenticate the version, binding and command digest, key reference and original thirty-day deadline. Ideas and plaintext keys do not enter the SQL archive. Command ciphertext, nonce and wrapped key remain in the encrypted envelope until disposal; retained identity and command digest provide the nonsecret audit record.

A bounded private poll selects up to100 already committed originals. SQL claim tokens expire after60seconds and renew every20seconds; retries wait at least30seconds. These leases exclude ordinary concurrent observations. The original provider and worker operation journals remain the effect fences if an older controller is still returning after a lease loss. A prepared original may take its first provider claim under its existing budget; an already claimed operation is lookup-only. No new admission, action budget, price, FX binding or provider operation is created by recovery. The actual shared metered executor recovers source, build, verification and exact settlement with the original immutable prices and FX. Unknown outcomes retain their reservation and never fabricate a charge.

Only toolchains in the mounted current/retained worker router are eligible. Unsupported toolchains, malformed ciphertext, wrong owner or operation, missing pricing, expired evidence and incomplete usage stay unresolved. Public session status remains read-only. The original signed event's cached response remains immutable, including usage_unknown; a new signed status query reads the latest durable action.

Install `migrations/phase-07/007_production_generation_recovery.sql` after the existing production accounting/metered schema and before starting the new runtime. Startup checks the archive relation before opening ingress. The migration is additive and repeatable. Old action, checkpoint, native provider journal, price and receipt bytes are not rewritten. Older writers can omit the archive; such legacy actions retain explicit original-command retry semantics. Rolling back the binary leaves the encrypted rows inert and preserves the financial history. Do not drop them as a rollback operation.

The poll erases the envelope, including its wrapped key and ciphertext, after the original becomes terminal or its retention deadline passes. Immutable owner/action/operation bindings, command digest and erasure timestamp remain. Expiry of uncertain work does not prove provider rejection and does not release money. Backup copies and KEK custody remain subject to the independent operational retention and restore gates; live erasure of this row alone is not proof of disposal from backups.

Tests use actual restricted PostgreSQL and production core/gateway/source/settlement classes with explicit model, worker and rail protocol fixtures. They cover transaction rollback, lost preparation COMMIT acknowledgement, concurrent controllers, expiry, immutable bindings, original caller maximum, and recovery from a dump restored into a second local PostgreSQL container. A separate upgraded candidate/profile/card/FX fixture proves the old receipt settles at its old exact amount without another paid POST or a caller resending the command. These tests do not certify live provider retention, worker isolation, cancellation, all eight release suites, cloud backup or production cutover.

The transport-claim-before-action-preparation window is covered separately by [protected funded generation intake](./production-generation-intake.md). Legacy pending markers without a companion still cannot reconstruct a command. The action archive proves recovery after preparation; intake recovery additionally requires its original verified-request and execution-context bindings. Likewise, a prepared original whose paid quote has expired needs the defined fresh-price consent path; receipt recovery does not license a new quote or dispatch. These remain release-blocking alongside cancellation and worker lifetime/grace verification.
