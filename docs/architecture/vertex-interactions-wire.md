# Vertex Interactions wire boundary

Tracked in [issue61](https://github.com/napplet/cvm/issues/61). This changes the
provider adapter's request/response handling, not ContextVM tools or normalized
billing/journal formats. It does not establish live provider acceptance.

The [official REST reference](https://docs.cloud.google.com/gemini-enterprise-agent-platform/reference/models/interactions-api)
and [SDK text format type](https://github.com/googleapis/js-genai/blob/dda511e175984ea4bb72b2e850ac7b7f520ea66a/src/gaos/models/interactions/text-response-format.ts)
were reviewed on 2026-10-28. Current text requests use content blocks; JSON output
uses a text response format with a MIME type and schema. Response usage has
`total_*` counters and output uses typed steps. The
[usage type](https://github.com/googleapis/js-genai/blob/dda511e175984ea4bb72b2e850ac7b7f520ea66a/src/gaos/models/interactions/usage.ts)
and [overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/interactions/)
provide the remaining field and stored-input context.

## Requests and original identity

The actual HTTP client sends one text content block and the current structured
JSON format. The text retains the original nonce, request digest, idea, system
instruction and output limit. Existing request/journal hash formats remain
unchanged. A fresh dispatch counts encoded input, system instruction, schema and
request framing against the approved input bound before its journal claim or
POST. Bounds that cannot cover this wire are refused; production limits are not
raised. This check is a conservative byte bound, not a measured tokenizer or
provider billing certificate.

A successful fresh POST may return generated steps without an input echo. Its
response is tied to that actual durably claimed POST. Explicit input evidence
must still agree with the original. GET/list reconciliation requires an exact
stored user-input match, including the nonce and full embedded request bytes.
A matching resource ID alone cannot substitute for that evidence. Conflicting,
duplicate, malformed or unrelated input remains unknown. Candidate/project
checks, the original paid-operation router and no-redispatch policy remain.

## Usage and output

Current counters are decoded as a complete set. Missing fields never become
zero. With tools disabled, the total must equal input plus final output plus
thoughts; cached input is part of input and is separated once for pricing.
Unsupported tool activity, mixed legacy/current fields, unexplained totals and
profile-limit violations remain unresolved. Optional modality details must
agree with the text-only totals, and grounding activity cannot add unpriced
fees. Authoritative live usage and billing
reconciliation remain required before production acceptance.

Typed model output text parts are joined into one bounded JSON result. Thought
summaries are excluded from generated app code. Unsupported step/content types
are rejected. An incomplete response with complete valid usage can yield a paid
incomplete receipt, without a fabricated artifact or generated result.

## Retained data and verification

Historical raw evidence has an explicit legacy decoder. Existing normalized
receipts, immutable prices, nonces and journal identities remain unchanged. A
synthetic original generated by the actual `fca7ce5` client replays through the
new reader without provider access or rewriting. No migration is needed.
Rollback preserves the records but restores the old client's inability to
interpret current raw responses; do not use that as a reason to reissue a POST.

Tests run the actual HTTP client and restricted PostgreSQL/gateway/source/core/
settlement graph with explicit current-format fixtures. They cover direct POST
without an echo, stored typed input after lost ACK and controller/pricing changes,
original charge/cap/FX preservation, malformed evidence, schema byte bounds and
legacy replay. Missing current usage counters also produce zero ledger debits
and zero builds in the actual SQL graph; a later complete original lookup
settles once. These are protocol fixtures, not paid API, live price, worker
isolation or release-suite evidence. Stored-provider retention and bounded
pagination fairness still need separate operational proof.
