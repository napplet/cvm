# Optional Modal report toolchain

The normal mounted Modal selector remains disabled. This image does not prove account eligibility, least-privilege RBAC, currency, original resource mapping, report coverage or finality. It grants no report or resource authority and is not selected by the current private deployment.

The production Dockerfile has an explicit `modal-billing` target for LinuxAMD64. Its final runtime combines the existing application and exact Bun1.3.14 binary with digest-pinned official Python3.14.8 on DebianTrixie. Trixie matches the pinned Bun image's [official source](https://github.com/oven-sh/bun/blob/bun-v1.3.14/dockerhub/debian/Dockerfile). The default `production` target retains the existing Bun control base. The optional image preserves UID65532, immutable source, private temporary storage, healthcheck and fail-closed production entrypoint.

`infra/production/modal-billing/requirements-linux-amd64.lock` pins Modal1.6.3 and28 transitive wheels. Every wheel was independently matched against the exact release's public PyPI JSON filename and SHA256; the public metadata is retained beside the lock. All downloads are binary-only and hash-required; installation uses only those downloaded wheels, with no index access. The original Modal wheel SHA256 is31e8952c8908740f3fbc666191fec78ff5fadecb7a48a29d40aed90b39531ffe. The Linux lock SHA256 is2560df0df7cf949bb1f08292967c2d654e6990a1b9668615392f1d70037a05d4. The resolver used explicit CPython3.14, cp314/abi3 and LinuxAMD64 manylinux tags as supported by [pip download](https://pip.pypa.io/en/stable/cli/pip_download/). [Hash-checking and binary-only installation](https://pip.pypa.io/en/stable/topics/secure-installs/) prevent resolution drift or source builds; matching PyPI hashes alone is not an independent upstream provenance attestation.

The exact hosted production-durability job builds both targets. Each is tested by image content digest with network disabled, read-only root, no capabilities, no privilege escalation and bounded disposable tmpfs. The optional-image proof checks root ownership and write permissions across the Python/venv runtime, executes a byte-identical private copy of the actual CLI with `--version` under the report runner's closed HOME/PATH/config environment, checks exact Python/architecture, compares every installed application distribution against the29-entry lock, and runs offline `pip check`. It also runs the existing pinned-helper/source-hash and missing-authority boot checks. Containers must be confirmed absent afterward. The test uses no credentials, account, report or model request.

The probe emits the exact image digest, executable and lock hashes plus observed versions and closure count. These are CI packaging facts, not release certification or permission to enable collection. No Linux image execution is established by the local macOS cross-download itself. Candidate selection, complete source/OCI measurement and the exact controller authorization remain later gates. Normal deployment and eventual certification continue through the root homelab command surface; do not manually deploy this target.

The first hosted optional-image check failed because a script copy cannot be directly executed on the default noexec tmpfs. The shared production/image helper now recognizes only the canonical image venv shebang and reads the verified private copy through its absolute Python interpreter with `-I`. It validates root ownership and absence of group/other write permission on interpreter paths and resolved parents; the candidate OCI binds the interpreter/dependency bytes. Completed child audits retain the measured interpreter SHA256. The image probe keeps explicit noexec and runs both the real CLI version path and the actual bounded report runner with a local fixture that only emits argv/environment facts. The fixture uses obvious fake token markers and performs no account/report/network call. This does not certify an authenticated provider report.
